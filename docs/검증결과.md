## 실제 Windows 실행 파일

사용자 복구 자료와 분리한 APPDATA, 검사 전용 루프백 디버그 포트에서 문서 카드 추가 전 EXE를 실행했습니다. 다음 9개 항목을 확인했습니다.

1. 실행 인자로 전달한 .agentsketch 문서 열기.
2. 담당자·사용자 필드·조건부 연결·경유점·그룹 설명·첨부 데이터 복구.
3. 실제 로컬 원본 존재와 파일 지문 확인.
4. 확장 문서 저장 후 디스크 JSON 전체 내용 일치.
5. 최근 문서와 버전 보관 API.
6. Windows OCR로 한국어 문장 인식.
7. 10개 업무 도구 패널 로드.
8. 두 번째 실행 요청의 문서를 기존 창에서 열기.
9. 네이티브 런타임 오류 없음.

그 뒤 정상 종료하여 마지막으로 연 문서의 최신 복구 파일이 보존됨을 확인했습니다. 강제 종료하지 않았습니다. 증거: output/native-upgrade-check.json, output/native-upgrade-final.json. Go 기본 검사에서 환경변수를 요구하는 OCR 통합 항목은 건너뛰며, 위 실제 네이티브 호출로 별도 검증했습니다.

기본 Windows 열기·저장 대화상자의 실제 파일 생성과 이미지 포함 재열기는 초기판에서 검사했습니다. 이번 확장은 네이티브 저장 API와 실제 디스크 전체 내용 비교, 실행 인자·두 번째 실행을 다시 검사했습니다. 모든 새 출력 형식의 Windows 저장 대화상자 조작을 각각 반복하지는 않았습니다.

## 출력과 문서 보존

실제 브라우저에서 PDF·PPTX·HTML·CSV·draw.io를 생성했습니다. PDF는 PyMuPDF로 한글 추출, Regular/Semibold 글꼴, 부분 굵기·색·크기와 렌더 이미지를 확인했습니다. 여백 20mm·200% 배율의 타일 출력에서 UI 예상 4쪽과 실제 4쪽이 일치했습니다. 표, 라벨 배경·회전, 이미지 자르기·회전을 확인했습니다. 증거: output/export-browser-check.json, output/pdf-rich-render.png, output/browser-export-tiled.pdf.

선택 저장에서 조건이 참조하는 요소가 빠져 재열기에 실패하던 결함을 수정했습니다. .agentsketch·CSV는 필요한 참조 요소를 함께 넣고, 실제 선택 저장→검증/가져오기 재열기로 조건 보존을 확인했습니다. 원본 문서와 PDF 등의 선택 범위는 바꾸지 않습니다. 증거: output/selection-export-check.json.

원본 .agentsketch는 선택 확장 필드를 더한 버전 1 JSON입니다. 기존 문서 읽기와 확장 문서 왕복 저장을 검사했습니다. 구버전 앱에서 다시 저장하면 구버전이 모르는 필드가 사라질 수 있습니다. 실제 PowerPoint에서 각 PPTX 객체를 편집하는 작업과 다른 제품의 모든 호환 기능은 검증하지 않았습니다.

## 메모리와 렌더 비용

문서 카드 추가 전 실행 파일에서 같은 16개 요소·9개 연결 예시를 새 프로필로 열고, 기본 GPU 비활성화·디버그 포트 없음 상태에서 20초 준비 후 10초 동안 Go와 WebView2 프로세스 트리를 측정했습니다. 보호 인자의 실제 적용과 정상 종료를 확인했습니다.

| 지표 | 최종 실측 |
| --- | ---: |
| 전용 상주 RAM | 99.85MiB |
| 전용 커밋 | 181.72MiB |
| Working Set 합계 | 411.77MiB |
| 유휴 CPU | 0% |

전용 상주 RAM은 공유 페이지를 제외하며, Working Set 합계에는 공유 메모리 중복이 포함될 수 있습니다. 단회·한 보드 측정이므로 모든 작업의 상한이나 일반적인 RAM 절감률을 의미하지 않습니다. 측정 원본: output/memory-upgrade/final-upgrade-comparison.json. 이전판의 같은 보드 단회 측정은 전용 상주 133.80MiB·커밋 185.31MiB·유휴 CPU 0%였습니다.

업그레이드 도중 합성 보드 렌더 CPU 중앙값은 1,000개에서 일반 7.4ms·전체 보기 8.0ms, 2,000개에서 일반 14.4ms·전체 보기 21.6ms였습니다. 2,000개 연결 경로는 최초 487.3ms, 요소 하나 이동 뒤 3.3ms, 표시 문서 projection 0.3ms였습니다. 유휴 추가 렌더 0회, 공유 이미지 디코딩 1회였습니다. 증거: output/upgrade-performance.json, output/upgrade-routing-performance.json.

이 렌더 수치는 마지막 PDF 출력·조건 UI·구간 고정 옵션 보완 전 개발 모듈 측정이며 문서 카드 추가 전 EXE의 FPS·입력 지연 측정이 아닙니다. 이전 경로 개선판의 2,000개 렌더 8.8ms·13.9ms보다 증가했으며 병렬 개발 부하도 있어 원인을 단정하지 않습니다. 새 메모리 측정은 위 문서 카드 추가 전 EXE 해시와 일치합니다.

상시 렌더 루프 없이 편집 시에만 다시 그립니다. 이미지·첨부 문자열을 이력에서 공유하고, 실행 취소·재실행 합계 추정 객체 예산 120,000개와 작은 보드 최대 60단계를 적용합니다. 비활성 문서는 디스크에서 필요할 때 읽습니다. PDF/PPTX 라이브러리·OCR·AI·공유는 필요할 때 사용합니다. 첨부·큰 이미지·내보내기 중에는 사용량이 높아질 수 있습니다.
